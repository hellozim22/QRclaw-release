对话与任务联动

对话如何驱动任务

  1. 新建会话后的首轮输入：系统根据你的描述判断是否要生成看板任务。需同时满足「目标清晰」（要解决什么）与「详情充分」（背景、范围或验收标准），才会自动创建任务并进入「进行中」。
  2. 执行过程中的任务同步：当智能体上下文即将压缩（对话过长需要摘要续聊）时，平台会提示把当前结论写回任务：更新任务目标与进度说明，并追加一条评论，避免换上下文后目标丢失。
  3. 完成与阻塞：对话正常结束会将关联任务标记为已完成；执行失败则标记为遇到阻塞，便于在看板跟进。

设计原则：对话负责探索，看板负责承诺与追踪，两者自动衔接，减少手工复制。

07 / 09
产品取舍

关于技能包

每个智能体底层都可以加载专属技能包，但当前版本不在界面中展示技能入口。原因：技能配置会显著增加上手成本；随着模型能力提升，大量细粒度技能的必要性在下降。后续若确有场景需求，再以可选高级能力形式开放。

ECC 工程标准

如何开始（ECC 标准）

本仓库按 Everything Claude Code 工程规范建设：计划与实现分离、测试先行、代码审查与安全审查、可重复的本地验收脚本。

本地启动

source ~/.config/qrclaw/secrets.env
bash scripts/setup-local-env.sh
bash scripts/dev-up.sh
open http://localhost:3000/chat

验收与质量

  • 单元与集成测试：cd tests && npx vitest run
  • 本地端到端：node tests/ecc-local-verify.mjs
  • 类型检查：gateway typecheck、web build
  • 进度与对话：node tests/capture-product-screenshots.mjs
