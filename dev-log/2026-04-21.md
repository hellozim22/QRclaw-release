- **D-TEST-GUARD**：`env.ts` 以 `VITEST`/`NODE_ENV=test` 为探针关闭 override。动机：保持生产行为（`override: true` 对抗 Cursor Cloud 的 stale shell env）不变，同时让 root 套件可以自由注入临时 env；比给测试加显式 `vi.stubEnv` 成本低。

## 安全事件（2026-04-21 自审发现）

本文件在 `0ee2960` commit 中**曾包含两处敏感值**：
1. Supabase Personal Access Token（`sbp_...` 开头，管理员权限）
2. `QRCLAW_KEK_V1` 值的首尾字符串（AES-256 KEK 的部分字节）

后续 commit（由本自审产生）已**前向 scrub** 这两处内容。但 `0ee2960` 的历史对象里仍保留原值，**在本地 `main` 未 push 之前**这不构成外泄。

**强制后续动作**：
- 用户已被告知应 **revoke 该 Personal Access Token** 并重新生成；聊天记录 + cursor session 里亦有同一值副本，revoke 是唯一彻底收口。
- 如果计划把 `main` push 到任何公开/半公开 remote，必须先 `git rebase -i` 重写 `0ee2960` 或 `git filter-repo` 清除敏感 blob，push 前 token 必须已 revoke。
- KEK 泄露风险：仅泄露头 8 字节 + 尾 9 字节（共 17/64 hex），理论不足以恢复完整 256-bit key，但下一轮维护窗口建议旋转 KEK（生成新值 + re-wrap 现存 DEK）。
