📖 概览：什么是 Agent Teams？

💡 一句话理解

Agent Teams = 你是 CEO，Claude 是 CTO（Team Lead），它帮你招聘和管理一整个 AI 开发团队。

每个"队友"（Teammate）是一个独立的 Claude Code 实例，有自己的上下文窗口，负责独立的开发任务，队友之间可以直接沟通协作。

传统方式 vs Agent Teams

维度传统（单个 Claude）Agent Teams（多个 Claude 协作）
并行度一次只能做一件事前端、后端、测试同时进行
上下文所有代码共享一个窗口（容易溢出）每个队友独立窗口，互不干扰
沟通只有你和 Claude 对话队友之间可以直接对话（如前端问后端 API 格式）
效率1x3-5x（取决于任务可并行度）
成本低高（每个队友都消耗 token）

QRClaw 项目为什么适合 Agent Teams？

QRClaw 是一个 前后端分离 + 实时通信 的项目，天然适合分工：

  • 🎨 前端（Next.js + Vercel）— Owner Dashboard + Visitor Chat
  • ⚙️ 后端（Node.js Gateway）— WebSocket 实时通信 + 消息路由
  • 🗄️ 数据库（Supabase）— Schema + RLS + Edge Functions
  • 🧪 测试（Vitest + Playwright）— 单元/集成/E2E

这 4 个方向可以并行开发，互不阻塞。正是 Agent Teams 的最佳场景。

🏗️ 第二步：理解 ECC 架构

ECC（Everything Claude Code）是 QRClaw 项目的 AI 开发标准。它不是一个工具，而是一套让 Claude 读懂你项目的配置体系。

ECC 文件结构

qrclaw/ ├── CLAUDE.md ← Claude 的"入职手册"（自动加载） ├── .claude/ │ ├── agents/ ← 13 个专业 AI 角色定义 │ │ ├── architect.md （架构师） │ │ ├── tdd-guide.md （TDD 专家） │ │ ├── code-reviewer.md （代码审查） │ │ ├── security-reviewer.md（安全审查） │ │ ├── e2e-runner.md （E2E 测试） │ │ └── ... │ ├── commands/ ← 31 个斜杠命令 │ │ ├── orchestrate.md （编排工作流） │ │ ├── plan.md （生成计划） │ │ └── ... │ ├── rules/ ← 自动加载的规则 │ │ ├── 01-foundation.md （基础规则） │ │ ├── 03-dev-workflow.md （开发流程） │ │ └── ... │ └── settings.json ← 权限设置 ├── requirements/ ← 你的需求文档 ⭐ │ ├── product-requirements.md （产品需求） │ ├── technical-specification.md （技术方案） │ └── ... └── design/ ← 设计文档 ⭐ └── qrclaw-design-report.html
💡 为什么 ECC 这么重要？

没有 ECC，Claude 就像一个刚入职的实习生，对你的项目一无所知。

有了 ECC，Claude 打开项目时会自动读取 CLAUDE.md，了解项目架构、编码规范、技术栈。然后根据 agents/ 中的角色定义知道"我是谁"、根据 rules/ 中的规则知道"什么能做什么不能做"。

Agent Teams 使用的关键文件

文件作用Agent Teams 如何使用
CLAUDE.md项目总入口Team Lead 和每个 Teammate 启动时都会自动读取
.claude/agents/*.md角色定义定义每个 Teammate 的专长和行为准则
requirements/*.md需求文档Teammates 据此实现功能，这是"做什么"的权威来源
.claude/rules/*.md编码规则自动加载，确保所有 Teammates 遵循同一套标准

⚡ 第三步：启用 Agent Teams

🔴 重要：Agent Teams 默认关闭

这是一个实验性功能，需要手动开启。不开启的话，Claude 无法创建团队。

方式一：修改 settings.json（永久生效，推荐）

# 打开 Claude Code 的全局配置文件
mkdir -p ~/.claude
cat > ~/.claude/settings.json << 'EOF'
{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  },
  "permissions": {
    "allow": ["Read", "Write", "Execute"]
  },
  "teammateMode": "tmux"
}
EOF

# 解释：
# CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS: "1"  → 启用 Agent Teams
# teammateMode: "tmux"  → 使用 tmux 分屏（每个队友独立窗格）

方式二：环境变量（临时生效）

# 在 .zshrc 或 .bash_profile 中添加
echo 'export CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1' >> ~/.zshrc
source ~/.zshrc

验证是否启用成功

# 启动 Claude Code
cd /path/to/qrclaw
claude-code-internal

# 在 Claude 的对话中输入：
请创建一个简单的 agent team 来测试功能是否正常

# 如果看到 Claude 开始创建 team 和 teammates → 成功！
# 如果报错说 agent teams 未启用 → 检查 settings.json

❓ 常见问题

Q: 队友做错了怎么办？

A: 直接在 Lead 窗口说："前端队友的实现不对，请让它回滚并重新按照 §P1 的协议格式实现"。Lead 会传达指令并监督修改。你也可以切换到队友窗格直接跟它沟通。

Q: 队友之间有代码冲突怎么办？

A: Agent Teams 的队友共享同一个代码仓库。如果两个队友修改了同一个文件，Git 会报冲突。这时你在 Lead 窗口说："请解决前端和后端队友在 types.ts 上的冲突"，Lead 会协调处理。

最佳实践：规划任务时确保每个队友负责的文件不重叠。比如前端只碰 web/，后端只碰 gateway/。

Q: Token 会不会很贵？

A: 会！每个队友都是一个独立的 Claude 实例。4 个队友 = 约 4 倍的 token 消耗。建议：

  • 队友用 Sonnet（便宜且快），只有 Lead 用 Opus
  • 不需要的队友及时关闭
  • 简单任务用 Subagent 而不是 Agent Teams
Q: 中途退出后怎么恢复？

A: Agent Teams 目前对会话恢复的支持有限（实验性功能）。建议：

  • 重要代码及时 git commit
  • 退出前让 Lead 总结当前进度
  • 重新启动后，告诉 Claude 之前的进度，重新创建团队
Q: 我的 claude-code-internal 版本不支持 Agent Teams？

A: Agent Teams 是较新的功能。如果你的版本不支持，可以：

  • 升级：npm update -g @tencent/claude-code-internal
  • 联系 IT 确认最新版本
  • 备选方案：手动开 3-4 个终端窗口，每个窗口独立运行 claude-code-internal，通过 CLAUDE.md 和 Git 共享上下文
Q: 可以在 Agent Teams 中使用 ECC 的 /orchestrate 命令吗？

A: 可以！Agent Teams 和 ECC 命令是兼容的。你可以让队友在自己的窗口中执行 /orchestrate feature 实现消息加密，它会在队友的上下文中运行 agent 工作流。
